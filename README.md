# Humanizer FA

فارسی طبیعی، با لحن انتخابی و حفظ معنا.

[English](README.en.md) · [لحن‌ها](references/tones.md) · [نمونه‌ها](examples/before-after.md) · [ارزیابی](evals/rubric.md)

یک اسکیل مستقل برای تولید، بازنویسی و نقد متن فارسی است. لحن خودمونی، صمیمیِ حرفه‌ای، رسمی، اداری، علمی، تبلیغاتی و ادبی را می‌توانید با زبان معمولی انتخاب کنید. حفظ عدد و شرط، نقش گوینده و اطلاعات فنی جزو قرارداد ویرایش است؛ متن برای جذاب‌ترشدن نباید حرف تازهٔ بی‌پشتوانه بزند.

## شروع سریع

[دریافت ZIP ریپو](https://github.com/usecluade88/humanizer-fa/archive/refs/heads/main.zip) یا دریافت با Git:

```text
git clone https://github.com/usecluade88/humanizer-fa.git
```

پوشهٔ اسکیل، یعنی پوشه‌ای که `SKILL.md` در ریشهٔ آن است، را در مسیر اسکیل‌های شخصیِ نصب خود قرار دهید؛ نام پوشه را `humanizer-fa` بگذارید و فایل‌های `references` را کنار آن نگه دارید. برای نمونه، در نصب Codex که اسکیل‌های شخصی را از `~/.codex/skills` می‌خواند، مقصد `~/.codex/skills/humanizer-fa` است. مسیرهای نصب می‌توانند بین محیط‌ها فرق کنند؛ از فهرست اسکیل‌های همان محیط برای تأیید کشف استفاده کنید.

پس از اینکه محیط اسکیل را در فهرست قابل‌استفاده نشان داد، در Codex می‌توانید بنویسید:

```text
$humanizer-fa
این متن را خودمونی ولی با خطاب شما بازنویسی کن؛ کوتاه و فقط متن نهایی:
«لازم به ذکر است که درخواست شما دریافت گردید.»
```

خروجی نمونه، نه تضمین خروجی دقیق مدل:

> درخواستتون رو دریافت کردیم.

این بسته prompt skill است؛ مدل تازه، افزونهٔ مرورگر، سرویس تحت وب یا برنامهٔ اجرایی humanization نیست. دستور فراخوانی در سایر عامل‌ها تابع همان محیط است؛ سازگاری عملی با همهٔ عامل‌ها آزموده نشده است. اسکریپت‌های کمکی به Python 3.10 یا جدیدتر نیاز دارند، اما خود اسکیل برای ویرایش نثر وابسته به اجرای آن‌ها نیست.

## انتخاب لحن و کنترل خروجی

درخواست طبیعی کافی است؛ لازم نیست همهٔ گزینه‌ها را پر کنید:

```text
این پاسخ را صمیمیِ حرفه‌ای و همدلانه بنویس، خطاب شما، حداکثر ۶۰ کلمه.
این نامه را رسمی‌تر کن ولی هیچ شرط و عددی تغییر نکند.
این متن را بازنویسی عمیق کن؛ همه اطلاعات بماند و قبل/بعد را نشان بده.
```

اگر کنترل صریح می‌خواهید:

```text
task=edit tone=samimi address=shoma strength=balanced length=short output=final
متن: ...
```

این عبارت‌ها راهنمای متنی برای مدل‌اند، نه گزینه‌های یک CLI یا API. [جدول قرارداد](SKILL.md) همهٔ مقدارها را توضیح می‌دهد.

| لحن | نمونهٔ درخواست |
| --- | --- |
| خودمونی | «مثل یک پیام راحت و محترمانه بنویس؛ خطاب شما بماند.» |
| صمیمیِ حرفه‌ای | «برای سایت برند، روشن و گرم با فعل نوشتاری بنویس.» |
| رسمی | «برای پیشنهاد همکاری؛ دقیق، محترمانه و بدون شکسته‌نویسی.» |
| اداری | «در قالب نامهٔ کوتاه سازمانی، بدون نام یا سمت ساختگی.» |
| علمی | «اصطلاح‌ها، دامنه و میزان قطعیت منبع حفظ شوند.» |
| تبلیغاتی | «متقاعدکننده باشد؛ وعده، آمار یا فوریت ساختگی اضافه نکن.» |
| ادبی | «روایت و تصویر بیشتر؛ دادهٔ واقعی را تغییر نده.» |
| سفارشی | «از این نمونهٔ لحن الگو بگیر و همین اطلاعات را بازنویسی کن.» |

خودمونی‌بودن با خطاب «تو» یکی نیست. همدلی هم لحن جداگانهٔ اجباری نیست؛ می‌توان رسمی و همدلانه نوشت. اگر خروجی از قبل خوب باشد، اسکیل می‌تواند آن را نگه دارد.

## برای چه کارهایی؟

متن سایت و محصول، پیام رابط، پاسخ مشتری، پیشنهاد همکاری، نامه، مقاله، محتوای شبکهٔ اجتماعی و ویرایش نثر فارسی. متن هر کاربرد لحن خودش را دارد؛ لحن درخواست شما الزاماً لحن خروجی نیست.

در یک سایت دوزبانه، این اسکیل برای متن فارسی است. هماهنگ‌کنندهٔ وب می‌تواند فارسی را به `humanizer-fa` و انگلیسی را به مسیر ویرایش انگلیسی بفرستد. این بسته به `website-design-orchestrator` یا Humanizer عمومی وابسته نیست و هیچ تنظیم سراسری را تغییر نمی‌دهد.

## چه چیزی را تضمین نمی‌کند؟

تشخیص انسانی یا ماشینی‌بودن متن، عبور از آشکارساز، رتبهٔ جست‌وجو یا کیفیت یکسان بین مدل‌ها تضمین نمی‌شود. اسکیل، راستی‌آزمایی تخصصی یا بررسی حقوقی نیست. خروجی‌های مهم را بازبینی کنید؛ بررسی خودکارِ رشته‌ها نمی‌تواند حذف یک قید ظریف یا همدلی مصنوعی را کامل تشخیص بدهد.

## بررسی و مشارکت

```text
python scripts/validate_package.py
python -m unittest discover -s tests -v
python scripts/check_invariants.py evals/cases.json path/to/outputs.json
```

دو دستور اول بدون مدل یا شبکه اجرا می‌شوند. دستور سوم به خروجی‌هایی نیاز دارد که واقعاً برای ورودی‌های corpus تولید کرده‌اید. روش داوری و محدودیت آن در [rubric](evals/rubric.md) آمده است. نتایج ثبت‌شده، در صورت وجود، در [گزارش ارزیابی](evals/RESULTS.md) هستند؛ از تعداد تست‌ها ادعای برتری عمومی نسازید.

در نسخهٔ ۲.۰.۱، [پنج نمونهٔ بلند با قبل/بعد](evals/long-form.md) هم اضافه شده‌اند. متن اولیه و نهایی هرکدام بیشتر از ۲۰۰ کلمه‌اند؛ این بخش خودبازبینی نویسنده است و آزمون کور یا داوری مستقل محسوب نمی‌شود.

برای گزارش مشکل، یک ورودی کوتاهِ بی‌اطلاعات خصوصی، لحن خواسته‌شده، خروجی و تغییری که در معنا/کاربرد رخ داده را بفرستید. [راهنمای مشارکت](CONTRIBUTING.md) را ببینید.
